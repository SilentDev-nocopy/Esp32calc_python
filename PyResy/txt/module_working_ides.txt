1. A Resiris module is a library for the Resiris Programming Language.

2. To be able to use a module you have to include it into the .resy file, by typing "<include> ModuleName"

3. As the Runtime reads the .resy file, it will import the given modules from the "Modules" folder. Every module including has to happen on the top of the file!
So it has to look like this:"<include> ModuleName
                               <include> ModuleName2" or "<include> ModuleName, ModuleName2"

4. If a module is not found then the Runtime gives an error:"{ModuleName} not found!" Error code:"MissingModule"

5. A module can have data and can give data like: int, float, string, bool, function.
A module cant have data like: UnknownObject, so every variant need to have a given value which cant change, so ideally use constants.

6. Modules will be written in C++.

7. The exact file format of the modules is currently unknown.

8. A module is a library/namespace, not a normal Resiris object.

9. The module can create its namespace after it is included, so the user does not have to create a variable for the module.

10. The data of a module should ideally be read once when the module is included, so later it can be used locally by the Runtime.

11. How to use a module:
"<include> ModuleName, ModuleName2

print_cmd(ModuleName.module_function_name(argument))

or

print_cmd(ModuleName.module_constans_value)"

12. Only int,float,bool,string can be argument! Otherwise gives error:"{given_argument} is not a usable modules argument!" Error code:"UnknownModuleArgument"

13. Module functions can return Resiris values.

14. Example:
<include> RSMath

v result float = RSMath.sqrt(25)

15. The "." is used to access functions and constants inside a module namespace.

16. The exact rules of the "." operator are not decided yet.

17. What is the exact structure of a module?
        When a module is included, load it and run its own "_INIT_" function.
        A module has to have atleast one constans variant, named "NAME" and its a string.
        If a module's functions is called from a currently running .resy file, run it then close it so it makes free memory.
        The point is to make every calculation in the start so in the remaining time the whole runtime runs smooter.

18. How does a C++ module register itself and its functions/variants to the Resiris Core?
        Every module will have 3 constans, one named "FUNCTIONS" which type is string, the second is named "VARIABLES" which type is also string.

19. What can a module export besides int, float, string, bool and functions?
        Nothing. Just int, float, string, bool, function. The functions type idealy used on the start so id doesnt have to run again and again.
20. Can a module have constants only, or can it also have other types of data?
        No, just constans!
21. What exactly happens when a module is included?
        Runs its own _INIT_ function which tells the runtime the module's NAME, FUNCTIONS and VARIABLES constans.
22. Can a module namespace be assigned to a variable?
        Yes but idealy the "caller variable" has to be upperthen any future function.
23. What exact rules apply to module functions and their arguments?
        To give an argument to a module function write "ModuleName.function_name(argument, argument2)
24. What types can a module function return?
        Every one of the usable type is "returnable". It means int, float, string, bool, FunctionalObject is returnable. Nothing else!
25. Can a module have internal state?
        Yes. On start, when scaning "INIT" Then when posting (aka. sending the 3 constans to the caller .resy file) "POSTING". When a .resy file is ask it to run a function then "RUNNING {FunctionName}". On exiting(to free up memory) "EXITED".
26. Does a module need an initialization function?
        Yes, inside it when called, otherwise no.
27. When does module initialization happen?
        On runtime start. Thats why we has to include ever module on the first line, so it has time to start.
